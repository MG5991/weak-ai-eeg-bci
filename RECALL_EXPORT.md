## 1. What this project is

Software + cross-dataset benchmark supporting a PhD (candidate-of-science) dissertation:
**"Models and Methods for Human–IoT interaction using Weak AI."**

"Weak AI" here means **narrow / task-specific** AI — not "low quality," not "weak learner" in the
ensemble-methods sense. The system classifies motor-imagery (MI) EEG signals into commands that
drive a **virtual** IoT device (a simulated drone or lamp).

The aspirantura defense is **already passed**. Everything in this repo is **post-defense** work
that feeds three planned journal papers and, eventually, the extended dissertation.

## 2. Hard constraints (non-negotiable, established with the user)

- **Fully offline and virtual.** No real hardware, no MQTT, no live Emotiv streaming. The virtual
  drone/lamp *is* the "IoT interaction." An `actuators.py` with an MQTT class exists in the repo but
  is abandoned — only `SimActuator` is used. Do not build toward real devices.
- **Honest framing is mandatory.** Cross-subject accuracies sit around 0.55–0.69 without
  `--subject-norm` — above chance (0.50) but below the ~0.70 threshold usually considered practical
  for BCI control. Describe results as **"preliminary feasibility,"** not a working BCI system.
  One config (BCI-IV-2b, all channels + `--subject-norm`) reaches **0.707**, but this is a single
  9-subject dataset with low fold power — it does not prove the threshold is generally cleared.
- **Self-Training does not beat supervised learning** on any of these datasets. Frame it as
  **label-efficiency / graceful degradation** (you can get close to supervised accuracy with only
  20% labels), never as an accuracy win. An earlier thesis-deck claim ("20% labels beat 100%
  supervised") did **not** reproduce and must not be repeated.
- On the **Emotiv** dataset, all 8 models are statistically tied (paired Wilcoxon across folds,
  Holm-Bonferroni corrected, 10 folds) — in every channel configuration tested (all, motor,
  +subject-norm). Do not claim a winner there. This is a small-sample artifact of low participant
  count, not evidence that "no dataset shows real differences" — PhysioNet (109 folds) clearly
  differentiates models.
- Frequency bands are **harmonized** to the Emotiv 6-band set everywhere: 4–8, 8–12, 12–18, 18–25,
  25–32, 32–40 Hz. Any numbers from before this harmonization are stale (e.g., an old BCI-IV-2b
  figure of 0.664).
- **Emotiv EPOC X has no C3/C4** (no true motor cortex electrodes). Its closest "motor" proxy is
  F3/F4/FC5/FC6 (premotor), and trimming to those channels *lowers* accuracy — a hardware-coverage
  limitation, not a bug. For proper 10-20 montages (BCI-IV-2b, PhysioNet), "motor" channels means
  C3/Cz/C4 and neighbours.

## 3. Repo layout

| File | Role |
|---|---|
| `eeg_engine.py` | Main entry point. Loads a dataset, selects channels, extracts harmonized band-power features, optionally applies `--asymmetry` / `--subject-norm`, runs the full model roster under Leave-One-Participant-Out (LOPO), prints a significance-annotated comparison table, writes `results_master.csv` + `folds_master.json` + `playback_*.json`, appends to `RESULTS_LOG.md`. |
| `significance.py` | Shared stats: Holm-Bonferroni correction + paired Wilcoxon pairwise significance across folds. Used by both the engine and `summarize.py`. |
| `summarize.py` | Reads `results_master.csv` + `folds_master.json` → writes `summary_report.md` (cross-dataset accuracy pivot + a hand-maintained "why do results differ" table). |
| `mi_experiment.py` | ML core: band-power extraction, self-training, `evaluate`, `print_table`. Also contains CSP/FBCSP/Riemannian code, which is **not used** by the engine anymore (removed from the comparison per the user). |
| `run_me.py` | One-click launcher; runs the engine on the user's CSV with `--subject-norm` by default. |
| `EEG_control_prototype.html` | Browser demo. Load sample / Upload CSV / **Load playback** (animates the virtual drone/lamp from a `playback_*.json`, with an IDLE fail-safe below a confidence threshold, and a dynamic accuracy badge). |
| `results_master.csv`, `folds_master.json` | Master result tables, deduped by dataset\|channels\|model — safe to re-run and overwrite. |
| `RESULTS_LOG.md` | Auto-appended lab notebook, one entry per engine run. |
| `summary_report.md` | Auto-generated by `summarize.py` — do not hand-edit. |
| `eeg_dataset_emotiv.csv` | The user's own Emotiv EPOC X dataset (14ch × 6 bands = 84 features, `movement` label, `participant` column). |
| **Not yet created** | `train_model.py`, `classify.py` — see Remaining Work below. |

**Model roster** (identical across every dataset): Decision Tree, Random Forest, XGBoost (falls
back to HistGradientBoosting if `xgboost` isn't installed, labeled "XGBoost/HGBT"), Shrinkage-LDA,
Logistic Regression, MLP(64), SVM-RBF (supervised, 100% labels), Self-Training SVM-RBF (20% labels).

**Datasets**: the user's Emotiv CSV, BCI-IV-2b (`--dataset 2b`, MOABB, binary L/R hand, dedicated
C3/Cz/C4 montage), PhysioNet MI (`--dataset physionet`, MOABB, L/R hand, 64ch 10-20, 109 subjects).

## 5. Verified results (harmonized bands, LOPO cross-subject accuracy)

| Dataset | Channels | Best model | Accuracy | Notes |
|---|---|---|---|---|
| Emotiv (user's CSV) | all-14ch | XGBoost | 0.606 | **All 8 models statistically tied** |
| Emotiv | motor-4ch (F3/F4/FC5/FC6) | Shrinkage-LDA | 0.566 | Trimming to motor proxy *hurts* — no true C3/C4 |
| Emotiv | all-14ch **+subject-norm** | **Shrinkage-LDA** | **0.658** | Biggest lever found on this dataset (+0.052 over baseline); still all tied |
| BCI-IV-2b | all (C3/Cz/C4) | Shrinkage-LDA / LogR | 0.689 | Only Decision Tree (0.560) not tied with best |
| BCI-IV-2b | all **+subject-norm** | **LogR / Shrinkage-LDA** | **0.707** | Crosses the ~0.70 line, but single dataset / 9 subjects / low fold power — don't over-claim |
| PhysioNet-MI | all-64ch | Logistic Regression | 0.595 | RF (0.544), Self-Training (0.535), Decision Tree (0.511) **not** tied — 109 folds gives real statistical power |
| PhysioNet-MI | motor-19ch | Logistic Regression | 0.589 | Trimming 64→19ch cost only ~0.006 (unlike Emotiv) |
| PhysioNet-MI | all **+subject-norm** | SVM-RBF | 0.620 | +0.025 over baseline |
| PhysioNet-MI | motor **+subject-norm** | Shrinkage-LDA | 0.600 | +0.011 over baseline |

**Key findings:**
- `--subject-norm` (z-scoring each participant's features using only their own trials before
  pooling) **generalizes across all three datasets**, and the gain is *inversely proportional to
  montage quality*: Emotiv (worst montage, no C3/C4) got the biggest lift (+0.052); the two clean
  10-20 montages got smaller but real lifts (+0.011 to +0.025). Interpretation: it mainly removes
  inter-subject baseline shift (skull/impedance/arousal), which is a bigger fraction of total error
  on weaker montages.
- `--asymmetry` (left-right hemispheric band-power difference features) was tried on Emotiv and
  **rejected** — it dropped every model's accuracy (0.606→0.589), likely overfitting given only
  813 trials for 42 extra features. The flag still exists but isn't recommended.
- **Accuracy tracks motor-cortex coverage, not channel count.** BCI-IV-2b's 3-channel dedicated
  C3/Cz/C4 montage (0.689 baseline) beats PhysioNet's 64-channel full-scalp montage (0.595) despite
  1/20th the channels.
- Linear models (Shrinkage-LDA, Logistic Regression) consistently win or tie for best across every
  dataset and configuration.
- Self-Training SVM-RBF is always ≤ supervised SVM-RBF — confirms label-efficiency framing, never
  an accuracy win.

## 6. Current status

The full benchmark matrix is complete: `results_master.csv` / `folds_master.json` cover all 9
dataset × channel-config rows (Emotiv: all / motor / all+subjnorm; BCI-IV-2b: all / all+subjnorm;
PhysioNet: all / motor / all+subjnorm / motor+subjnorm) × 8 models = 72 rows. `summary_report.md`
is regenerated and reflects all of it. The subject-norm generalization question (does it help
beyond Emotiv?) is now answered — yes, and it scales inversely with montage quality.

## 7. Remaining work (priority order)

1. **Model persistence** (next up, not started): `train_model.py` to train the chosen model and
   save a `model.joblib` bundle (fitted estimator + `StandardScaler` + feature/band/channel spec +
   class→command map). Then `classify.py` (or an `eeg_engine.py --model model.joblib` mode) to load
   and predict without retraining, and emit a `playback_*.json`.
   **Known gotcha:** if `--subject-norm` is the shipped config, a *new* subject's own trials are
   needed to compute their mean/std before their data can be normalized — persistence design needs
   a small per-subject calibration step, not pure load-and-predict on raw features.

## 8. Working conventions / gotchas

- `eeg_engine.py`, `mi_experiment.py`, `significance.py`, `summarize.py` must stay in the same
  folder — engine and summarize both import from these.
- `xgboost` is optional; without it, results fall back to HistGradientBoosting (labeled "XGBoost/HGBT").
- Re-running a dataset+channels config overwrites its rows in `results_master.csv` (deduped by
  dataset|channels|model) and refreshes its folds — safe to re-run at any time.
- Do not reintroduce CSP/FBCSP/Riemannian features or MQTT/real-hardware code unless the user
  explicitly asks.
- Environment: Debian/Ubuntu, Python 3.12, externally-managed → must use the venv
  (`source ~/eeg-app/.venv/bin/activate`), use `python` not `python3` inside it.
- Git commits in this repo should **not** include a "Co-Authored-By: Claude" trailer — the user has
  asked for this explicitly.
